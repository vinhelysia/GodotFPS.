BLOCKERS FOUND IN INITIAL FIXTURE SNAPSHOT (primary was notified immediately)
1. P1 — Structure lookup is overwritten by76 NavigationObstacle3D nodes.
   tests/town500_composition_regression.gd:53-55 collects any Node3D carrying a
   catalogue town500_id. Scene/World/Town500m/navigation_exclusions.tscn:5,14
   gives T01-A's obstacle the same ID as the physical building; repeats for76.
   town500_integrate.gd payload dictionary puts RoofNavigationExclusions last.
   Therefore buildings[id] becomes an obstacle. Count remains76 and misleadingly
   passes, but _navigation():94/98 and _interiors() ask these obstacles for Markers.
   Minimum fix: exclude NavigationObstacle3D/roof_exclusion_only during lookup,
   then assert uniqueness of actual structure IDs (not only dictionary size).

2. P1 — Rotated Player ROOT makes world-space walking aim90 degrees wrong.
   Initial town500_integrate.gd:72 copied RaidSpawn.transform to Player.transform;
   line69 set RaidSpawn yaw to the contract's -90 degrees. Composition fixture
   _walk():222 sets body.rotation.y with world-space atan2. Cogito movement uses
   body.global_transform.basis (cogito_player.gd:1087,1093). Root yaw therefore
   adds another -90 degrees to every steering direction.
   Minimum fix: player.position=RaidSpawn.position; keep Player root rotation
   identity; set player.body.global_rotation to marker rotation. This matches
   cogito_scene.gd::move_player_to_connector. Alternatively aim global rotation,
   but correcting composition also preserves native connector semantics.

COVERAGE / FIXTURE LIMITS THAT STILL NEED PRIMARY ACCEPTANCE
3. _navigation():111-131 tests vertices only. Zero wet/roof vertices does not
   prove zero polygons crossing wet/roof interiors: an edge or large polygon
   can span an excluded area with all vertices outside. Also does not prove
   obstacles are included in the bake. Keep vertex residue as diagnostic, add
   representative closest-point/reachability probes or polygon intersection
   checks using actual baked polygon geometry. Do not delete polygons by centroid.

4. _walk():206-229 checks grounding/floor only at its endpoint; transient airborne
   motion, stair jumps or fall damage during interior walks can be missed.
   Routes do compare initial/final health; interiors currently do not.
   Reuse terrain fixture's _feet_y(), grounded tracking and health invariant;
   retain allowance needed by native step behavior rather than inventing new
   controller code. Existing terrain fixture also releases every movement action.

5. Existing phase2 terrain regression owns actual bridge/deck/dock crossings,
   rails walk+sprint-jump blockers, water overlap/death and perimeter checks.
   New composition fixture has navigation/routes/interiors/capture phases only.
   It does not itself exercise gate collision, rail negative attempts, bridge
   approach continuity with new dressing, dock access, wet falling, sealed-roof
   physical entry, or production LOS standing/ADS/lean/scope. A previous isolated
   payload pass cannot certify changed production composition. Reuse scoped phase2
   helpers / existing weapon probes against the actual composed Town.

6. Compatibility town_expansion_regression.gd is now only an extends entry point.
   Its default runs navigation queries; it no longer provides its old physical
   traversal/deployment coverage. Eight route phases plus interiors must all run
   and have fresh reports before calling full physical acceptance complete.
   gameplay-placement-proposal.json reuse_tests references old line245/311 helpers
   that no longer exist in this compatibility file; those references are historical.

7. Prerequisite failures currently call _check then continue: missing76 physical
   structures or unsynchronized navigation may lead to Dictionary/get_node errors
   before _finish writes a report. Minimum fix: early return through _finish for
   missing structure IDs; keep failed receipts separate from runtime exceptions.
   Capture/report writing also assumes tests/artifacts/town500_phase3 exists;
   create its owned directory once if not guaranteed by the primary workflow.

READ-ONLY REVIEW — four-quadrant offline navigation bake proposal
No MCP, bake, script edit or runtime execution performed for this review.
Observed empty/full bake results and editor crash are primary-provided evidence;
this review does not independently reproduce them or establish crash root cause.

Assessment: defensible smallest workaround, PROVIDED seams are verified rather than
assuming coordinate welding guarantees connectivity. Keep the exact parsed source,
agent values, masks, roof obstacles and ledge/clearance flags in all four bakes.
Nominal cells are2500x2500 per tile, with2520x2520 including1m apron per side;
this reduces per-bake field size substantially while preserving0.1m resolution.
Recast upstream rcCompactCell stores a24-bit span index. That is a plausible size
limit for the reported5000x5000 field, not proof of this Godot crash or empty bake:
actual compact span count depends on coverage/stacked layers and exact engine code.
Primary source: https://raw.githubusercontent.com/recastnavigation/recastnavigation/main/Recast/Include/Recast.h

Godot documents expanded baking bounds + inward border_size for aligned tile edges;
border affectsXZ only; edge_max_error must be<=1 for that property combination.
Thus quadrants [-250,0]/[0,250] in both axes, expanded1m on everyXZ side with border1,
should produce nonoverlapping canonical250m outputs. Do not concatenate the apron
as overlapping navigation surface, and do not approximate a crop by centroid deletion.
Official references:
https://docs.godotengine.org/en/stable/classes/class_navigationmesh.html#class-navigationmesh-property-border-size
https://docs.godotengine.org/en/stable/tutorials/navigation/navigation_using_navigationmeshes.html#baking-navigation-mesh-chunks-for-large-worlds

Minimal correctness assertions before assigning merged mesh to production Region:
1. Every tile has finite vertices and >0 polygons. Record tileAABB, vertex/poly counts,
   exact bake properties, parsed source hash/count and obstacle count. Await each bake
   completion before reading/merging; never mutate a shared source/nav during its bake.
2. Same world frame, cell grid and Y minimum/height for every tile. Tile origins/aprons
   must be integer multiples of0.1m. Reset filter_baking_aabb_offset if inherited.
   Region/root transforms stay identity. Confirm outputs in canonical tile bounds
   (small float tolerance), not252m apron bounds; no double world translation.
3. Vertex weld comparesXYZ, with tiny roundoff tolerance only; no0.1m rounding/snapping
   of arbitraryY or wide epsilon merges. Different floors must remain different.
   Assert valid polygon indices,>=3distinct indices, nonzero area, consistent winding;
   deduplicate identical polygon cycles and reject nonmanifold edges (>2owners).
4. Along internalX=0 andZ=0, coordinate coincidence alone is insufficient. A long edge
   opposite two short edges is a T-junction; endpoint welding will not create matching
   complete adjacency. Build undirected edge-pair diagnostics and identify unmatched
   collinear seam intervals in intended dry walkable corridors. If present, repair
   exact edge segmentation or reject merge; do not widen gameplay corridors or add
   NavigationLinks to hide the defect. No need to force water/building-blocked intervals
   to connect. Do not rely on cross-Region edge_connection_margin with onlyONE Region.
5. Preserve source terrain/water exclusions/76roof obstacles and rerun existing23GF,
   four upper, wet/roof samples, ports and8full physical routes after merge. >0polygons
   and one route query are insufficient. Publish resource only once checks pass or
   retain explicit pending status. Keep offline helper as reproducible bake owner;
   an ordinary future full500m editor rebake would repeat the unresolved limitation.
